02今天新挖到的五件事

① 回合边界是干净的

bs_start_round → 下一回合开始。实测 71 次。回合内每个单位的行动有完整的开始/结算状态，跳过行动的单位也留痕。

② 命中判定居然记录了

每次挥击都会写 Chance to hit: 0.85 和 Roll to hit: 0.47。比较两者就知道中没中——「刀锋擦着它的肩甲过去」这种句子现在有事实依据了。

③ 地图是被逐格记录的

move to area 'coMN', tile 0 进走廊/'rooN' 进房间，Moved onto areatile N 每走一格一条。房间与走廊的名字直接来自关卡图，不用猜。

④ 本地化是一整座金矿

72.2 万个字符串表条目，68,748 条中文；188 个职业（含你的 mod 职业）能提取出技能名和 70 条上下的角色台词。

⑤ 但有两件事必须说清楚

拿不到：伤害数值、技能名

日志整套翻完，只有状态机、命中、暴击、击杀，没有一处写「造成 17 点伤害」或「使用了惩戒」。所以旁白只能写「重手」「接连两下落实」这类表达——这反而逼出了更好的文风，但它确实是信息损失。

会踩到：mod 的乱码与缺名

你的「旧裔（Octopus）」mod 台词文件是 GBK 存成 UTF-8，直接读出来是「鐤戞儜鍓嶆柟」。已加自动修复；另外 nullptr、### 这类缺名也做了兜底。

04抗噪：为什么刷副本不会再被写成文章

这是你那条反馈里最要命的一点。一个只靠「事件触发」的旁白系统，在低难度副本里会不停地说话，最终变成另一种流水账。所以加了一层显著性打分：

# 每个回合窗口算一次
score = 0.4 × 命中次数
      + 3.0 × 是否有重手（暴击）
      + 2.5 × 放倒数
      + 1.5 × 治疗次数

if score < --salience:   # 默认 2.5
    静默   # 什么也不说

你的两趟副本实测：89 个候选场景 → 82 个真正输出，被砍掉的都是「四个人各挥一下、无事发生」的回合。往下调到 4.0 会更吝啬，只在高潮时说话——这个值应该由你自己玩着调，它其实是「旁白的密度旋钮」。

同样的逻辑适用于地图：走过 5 格、什么都没捡到的走廊，不产出旁白。

05敌我识别：为什么不能靠坐标

我第一版用「屏幕 x 坐标小于 700 就是我方」，这一版把它推翻了。证据：同一局的两场战斗里，我方英雄的 x 分别是 542 / 388 / 234 / 80 和 780 / 626 / 472 / 318——镜头和队形会让坐标整体平移，任何写死阈值的判断迟早出错。

现在的做法是拿 RERANK-POS 里的 (guid, 职业) 去对存档：两个字段同时匹配才算我方。日志里怪物 guid 会和人撞号（比如 guid=98 既是一具骷髅、也是你名册里的一位英雄），但配上职业就唯一了。这条规则不依赖分辨率、不依赖镜头、不依赖 mod，只要存档还能解码就一直有效。

还有一个坑：行动者日志打印的是职业显示名（helli → 「狼女」），而暴击日志打印的是英雄本名（「御影」）。所以旁白里出现「御影」是查表换回来的，不是猜的。

06职业档案：能读到什么，读不到什么

你希望读铁匠铺 / 工会 / 生存帐篷里的职业介绍。实测结论：DD1 没有一整段散文式的职业介绍。那三个界面显示的是结构化条目——职业名、技能名、升级树名称、技能效果描述、以及英雄台词。这些都由 .string_table.xml 提供，我已经全部抽出来了。

以你的 mod 职业「星火·灾星（FYDT）」为例

  • 中文名：星火·灾星
  • 技能：惊骇之爪、横扫尾击、切入、恶火拖拽、飘渺、融化命运、重构、隔离、剥夺…
  • 台词标签：shuffled / startmoving / increasingstress / bigwound…
  • 台词样例：「愚蠢，是治不好的。」「嗯哼哼～」

另三种可用素材

  • 怪癖：名称 + 描述（例：赌术糟糕 / 气血稳健）
  • 折磨：名称 + 描述（例：偏执、自残、非理性）
  • 物品：名称 + 描述（例：翡翠、画像、静伏之种）
  • 台词：每个职业约 70 条，按压力/移动/濒死/暴击等情境分类

台词是这套东西里最值钱的：它既是角色卡（这个人在害怕时说什么），也是文风锚（让模型模仿这个人说话，而不是让它自由发挥）。生成时按情境挑 2–3 条塞进 prompt，比写一段「该职业性格内向」有效得多。

07文风：旧样章的问题与三段新样章

你说得对。之前那段六百字能成立，是因为它被当成一篇文章来读；在游戏里，玩家刚打完一个回合，屏幕上只有几秒钟的注意力。所以要改的不是文笔，是单位——从「章节」改成「一句话的呼吸」。

09稳定性与 mod 兼容：九条硬约束

对游戏

  • 只读。不改 exe、不注入进程、不写存档、不装 mod。
  • 日志按字节偏移增量读，日志被清空或轮转时自动归零重读。
  • 存档可能被游戏占用：解码失败静默跳过，下个周期重试。
  • 寻址不靠坐标、不靠内存偏移、不靠版本号。

对 mod

  • 职业/怪物/物品/怪癖识别全部走本地化字典，255 个 mod 自动纳入。
  • 缺名（nullptr、###）降级为可读兜底，不中断。
  • mod 文本乱码自动尝试 GBK→UTF-8 救回。
  • 新装 mod 后跑一次 build_loc.bat 重建字典即可。
  • 同职业两人时退回职业名调用，不猜错人。

不打算做的：内存读取 / DLL 注入。它能把上面那项补到 100%，但每次游戏更新、每加一个 mod 都可能崩——与你「稳定性和兼容性优先」的要求直接冲突。

关于成本：一次场景调用的输入约 300–600 token（比 v1 小一个数量级，因为只给最近两回合），输出 60–150 token。一晚十趟副本大约几十次调用，花费在几毛钱量级。
